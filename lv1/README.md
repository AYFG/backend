# LV1 — 백엔드 입문: "설명할 수 있는" 개발자로

> 이 폴더는 단순한 학습 기록이 아닙니다.
> **"암기가 아닌 이해, 이론이 아닌 경험"** 으로 배우는 철학을 실천하는 공간입니다.

---

## 🧭 이 폴더의 학습 철학

### 1. "경험"으로 답변하라

면접에서 `"JPA가 뭔가요?"` 라는 질문을 받았을 때,
구글링한 정의를 외우는 사람보다
**"JdbcTemplate 지옥을 겪어봤는데요..."** 로 시작하는 사람이 된다.

→ 코드를 치기 전에 외우지 말고, 부딪히고, 깨닫고, 체화하라.

### 2. Why → How → What

무작정 코드를 따라치지 말고,
**"왜 이렇게 설계됐을까?"** 를 먼저 질문하라.
프레임워크의 철학과 구조를 이해한 뒤에야
코드가 진짜 내 것이 된다.

### 3. 결과물을 만들어라

이 폴더의 최종 목표는 개념 정리가 아니라
**실제로 작동하는 무언가**다.
Todo List든, 작은 API든,
"이거 만들어봤어요"라고 말할 수 있는 포트폴리오를 목표로 한다.

### 4. 핵심 흐름에 집중하라

모든 것을 다루려 하지 않는다.
**꼭 알아야 할 흐름**이 끊기지 않게 하라.
하나를 배워도 그 연결고리를 이해하는 것이 더 중요하다.

### 5. 면접은 정의 싸움이 아니다

면접관이 듣고 싶은 것은
"어떻게 했냐"가 아니라 **"왜 그렇게 했고, 무엇을 느꼈냐"** 이다.

## 📂 폴더 구조 철학

```
lv1/
├── README.md          # 이 철학 — 반드시 먼저 읽을 것
├── practice/          # 직접 부딪히며 실험한 코드
├── projects/          # 실제 작동하는 결과물
└── notes/             # Why 중심의 학습 기록 (정의 암기 금지)
```

- **practice/**: 그냥 돌려보고, 에러 내보고, 깨지는 코드
- **projects/**: "이거 만들어봤어요" 할 수 있는 실제 포트폴리오
- **notes/**: "JPA는 ORM입니다" (X) → "JPA를 쓰니 SQL 반복이 사라졌다" (O)
